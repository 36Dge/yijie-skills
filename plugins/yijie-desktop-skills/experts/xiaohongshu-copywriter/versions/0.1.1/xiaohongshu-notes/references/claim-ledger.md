# 逐条主张核验

版本：0.1.1。

## 先建立证据边界

用 F1、F2 编号列出本轮用户明确提供或本轮已核实的商品事实；明确的目标市场/人群是定位输入，不是商品性能。旧聊天中的模型文案、普通行业常识、参考模板和“通常如此”不能成为本商品的证明。冲突或缺失信息列待确认，不在正文补齐。

## 从事实到文案

每个可验证的描述必须能直接由一个事实支持。可同义改写和准确换算单位；不得增加强度、范围、比较、因果、体验或适配性。例如：

| 事实 | 可用表述 | 不能自行推导 |
| --- | --- | --- |
| 杯盖可拆洗 | 杯盖可拆洗；lid can be removed for cleaning | 清洁无死角、每个角落都能洗、减少残渣/异味、易洗/更易洗、洗碗机适用 |
| 容量350ml | 350ml（约11.8 US fl oz） | 每人一杯刚好、更轻便、不占空间、适合车载杯架 |
| 拉链开合、两个内袋 | 拉链开合；设有两个内袋 | 防盗、防水、更安全、更耐用、容量很大 |
| 三档亮度、USB供电 | 三档亮度；USB供电 | 护眼、减少疲劳、节能、所有充电器适配 |

“可帮助”“可能”“草稿”“适合”不能使无证效果变成可发布主张。尚未证明的产品效果放入待证清单，不能夹在标题、正文、英文Bullet、标签、字幕或口播里。创作假设仅限镜头安排、渠道、叙事和排期，并明确标注；不能假设商品性能。

## 交付前逐句检查

先写草稿，再对标题、封面/主图、正文、卖点、标签、视频口播字幕逐项回看。把每句具体商品主张与F编号对齐；对不被证据直接支持的修饰词或收益句删去或改成事实描述，然后交付修正稿。资料少时可用不同场景表达同一事实，不为了凑3个卖点发明第3个属性。

附简短“主张—事实编号”对照以及待确认项；若仍有无法支持的句子，必须继续修正，不能宣称全部核验通过。只读了参考资料不等于商品效果已验证，任何自评都不能替代用户真实证据。
