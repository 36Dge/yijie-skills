# M03 上架 SOP

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。

## M03-01 类目与基础字段

状态：reviewed-reference；原稿：344–369、405–426、552–569、1918–1919。

输入：商品用途、品牌/型号、材质、规格、实际库存与履约能力。

1. 在当前发布页按真实用途查类目说明；竞品仅供比较，不因竞品选择就认为类目必然正确。
2. 核对类目与资质匹配，再填写属性；识别可选属性是否影响买家筛选。
3. 建立 SKU 表：规格名称、规格图、条码、可售库存、价格、差异说明。每张图与实际规格一致。
4. 有官方标准品预填时逐项确认品牌、参数和图文，不能直接发布系统带出的未知事实；没有入口使用正常手工流程。

输出：字段、证据原文、已确认值、待确认项的来源表。已确认值只转录有明确证据的事实；记录缺失保持“待确认”，不能改写成零值、“无”或“不存在”。店铺阶段不能替代商品历史的证据；需要推断时另列条件与推断，不混入已确认值。库存按可交付数量，发货承诺按实际能力，不用虚高数量吸引下单。比较申请可售量 Q 与已确认可交付量 A：Q<A 表示申请值低于已知可交付量，不能因此判虚高；Q=A 仅表示两值一致；Q>A 表示超过已确认可交付量，需核实或调整申请。A 或 Q 未知时不判断高低，也不推定申请目的。任何数值关系都不代表已获准修改库存。

待核实：发布入口、类目可修改性、条码与资质要求，原稿的统一修改周期不得当现行规定。

## M03-03 标题与真实商品信息一致性

状态：reviewed-reference；原稿：370–388、429–442、555–564、1894–1901。

输入：已确认品牌、产品名称、核心用途、材质/规格、目标搜索意图与可证明卖点。

1. 以“品牌/产品名称/关键用途或属性/规格”生成可读标题，不必每项都重复堆叠。
2. 核对标题中的每个事实是否能在产品或资质中找到依据；他人商标、无关热词与未证实销量不进入标题。
3. 对照主图、详情、SKU 和后台属性，列出不一致字段；同一单位与规格采用同一种表达。
4. 详情按用途场景、核心特点、规格/使用方法、证明材料、真实售后条件排序；未知保修或效果标待填。

输出：建议标题、逐词依据和一致性问题表；用户未确认的字段用占位标记，不编造热销标签。

待核实：当前字符/字数限制、类目命名规范与标签申请条件；原稿不同长度口径不自行取一个冒称官方。

## M03-10 上架前后检查

状态：reviewed-reference；原稿：443–475、510–574、1921–1946。

输入：待发布商品页面或脱敏字段、配送/售后模板、预期访问渠道。

1. 发布前预览每个 SKU：图片、价格、库存、优惠叠加、发货与退货承诺；按不同地区检查可售和运费。
2. 代发核对真实供货、库存同步、官方支持的发货方式与售后责任；不伪造或变更物流身份。
3. 发布后从实际用户视角检查链接、规格选择、视频关联、促销展示和客服入口，记录问题与修改时间。
4. 若用户提供搜索/推荐曝光，分渠道记录日期、曝光、点击、成交；曝光不能单独证明“已入池”或动作因果。

输出：发布前待修项、发布后观察表与回查日期；不自动点击发布。

待核实：电子面单、集运、商品素材工具和平台流量入口规则；不复制关闭某开关或转换单号的绝对命令。
