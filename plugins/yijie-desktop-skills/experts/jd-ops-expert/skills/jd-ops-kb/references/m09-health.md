# M09 店铺服务质量与复购

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。

## M09-01 店铺健康定位

状态：reviewed-reference；原稿：1185–1196、1229–1249、1300–1315、2153–2156。

输入：当前后台指标名称、计算时间、店型、用户提供的脱敏趋势与问题反馈。

1. 区分店铺星级、商品价格指标与体验/风向标，不把不同对象的分数当同一指标。
2. 按用户实际后台的评价、客服、物流、售后、纠纷维度找下降项，记录分母和观察周期。
3. 将下降项对应到真实问题：缺货、响应积压、商品描述偏差、物流延误或售后流程不清。
4. 排出可改善的原因与负责环节；先修履约和服务，不靠交易/评价数据操纵提分。

输出：指标→证据→原因假设→负责人与复查方式。原稿星级/订单数阈值不作为现行门槛。

待核实：当前店型是否参评、指标权重、保护期和活动适用条件。

## M09-05 评价与投诉的正常处理

状态：reviewed-reference；原稿：1250–1264、661–670、1993–1994、2170–2177。

输入：脱敏评价正文、已知商品/履约事实、用户已采取的正常售后动作。

1. 区分产品质量、信息误解、物流、客服体验与无法判断的内容，不因低星或无文字就认定无效。
2. 先解决事实问题：补充说明、排查批次、改善包装、提供适用售后方案；记录反馈不要求改好评。
3. 只有可举证的违规评价才整理正常投诉材料；引用当前评价规则、事实与证据，不伪造聊天或承诺通过。
4. 回复用具体处理方式和真实进度，避免公开买家个人信息或与客户争论。

输出：问题分类、内部改进项、可供用户审核的回复草稿/证据清单。

待核实：投诉范围、时限、复核能力与评分计算；原稿“基本都通过”“回复默认好评提分”不采用。

## M09-08 复购与日常运营

状态：reviewed-reference；原稿：1274–1298、1303–1314、2180–2183。

输入：商品消耗周期、已授权的汇总客户分层、退货与复购趋势、现有会员/促销能力。

1. 根据真实复购间隔区分新客、重复购买者与长期未购者，不能统一设一个固定召回天数。
2. 比较质量、配送和售后是否影响再次购买，先解决服务问题，再评估券或组合装成本。
3. 触达建议仅写为提案，尊重用户许可、平台渠道与退订设置；不自动发送短信/消息。
4. 日常回看评价、流量、活动到期和广告贡献，用同一时间表记录问题与行动，防止只看总销售额。

输出：分层假设、权益成本、适用渠道、复查指标和不应触达的范围。

待核实：会员/消息能力、发送授权、优惠规则；无“达到某复购率必优秀”的统一结论。
