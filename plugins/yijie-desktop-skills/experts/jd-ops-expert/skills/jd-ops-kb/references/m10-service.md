# M10 客服与售后

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。

## M10-01 售后首次接待

状态：reviewed-reference；原稿：1319–1328、2185–2186。

输入：用户描述的问题、已知商品/履约事实、商家真实售后政策；不需要真实订单号或客户联系方式。

1. 先确认问题和需要核实的最少证据，如破损位置、规格差异、是否影响使用；照片仅在确有必要时建议由正规售后入口提交。
2. 说明下一步将如何核对，给真实可承诺的反馈时间；没有商家时效资料就用待填字段。
3. 按适用政策提供退款、退换、维修或补发等可选方案，分别写条件、费用承担与预期流程，不能替商家批准。
4. 用户选择后由实际客服走正常服务单；草稿记录待办与回访点，不在对话里假称退款已执行。

输出：事实摘要、待核项、方案比较、可发送草稿及下一步责任人。

待核实：适用售后政策、商品条件和真实退款/补发时间，不复制原稿固定天数。

## M10-02 售前问答与催付草稿

状态：reviewed-reference；原稿：1329–1342。

输入：可确认规格、价格/活动、库存、发货和售后事实，以及客户具体疑问。

1. 先回答疑问本身：规格是否适合、价格包含什么、何时可发、出现问题怎样处理。
2. 对质量说明使用材质/工艺/检测等真实依据，不用“保证满意”“绝不变形”代替证据。
3. 库存紧张、优惠到期、赠品或加急仅在实际存在时使用；未知信息用待填，不用无依据稀缺促付。
4. 催付仅提供一次合适的服务式提醒草稿，是否发送、频率和渠道由用户及平台规则决定。

输出：建议回复与每个事实的来源；不自动发送消息，不制造“系统即将关闭”的假状态。

待核实：当前促销、库存和履约承诺；这些属于用户业务事实，不是模型推断。

## M10-04 服务指标与争议准备

状态：conflicted；原稿：1343–1363、1488–1500、2225–2234。

输入：店型、适用条款、违约/争议通知时间与原因、脱敏服务记录。

1. 先分清大陆 POP、全球购及其他合作模式；原稿全球购量化阈值不能直接适用所有商家。
2. 将通知中的指标、分母、统计窗口、时限和申诉入口逐项摘录；没有原文就标待核，不凭记忆填金额或天数。
3. 证据按事件时间排序：问题提出、真实回复、实际方案、履约/处理结果；保留原始记录，不伪造或篡改。
4. 形成事实陈述和待解决请求，先使用正常平台工单/申诉渠道；不把争议胜负作保证。

输出：时间线、材料清单、未确认规则与待办提醒提案。

待核实：回复考核、申诉期限和处罚适用性；原稿 72 小时与 7 日不统一选一。
