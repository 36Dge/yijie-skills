# M06 新店与新品冷启动

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。

## M06-01 上线准备与真实反馈

状态：reviewed-reference；原稿：896–920、976–980、2083–2087。

输入：商品资料、库存/履约能力、目标客户、正常获客渠道和可用预算。

1. 先完成类目、标题、图文、属性、规格、配送与售后的一致性检查，参考 M03-01/M03-10。
2. 区分页面缺项与经营数据不足，先修可确定缺项，不将“缺评价”解释为应安排人为交易。
3. 使用真实订单与自愿、客观反馈了解疑虑，汇总用户关心的规格/体验问题，改进页面和服务。
4. 若考虑官方试用/新品活动，由用户核实适用规则、费用、库存与反馈条件，不要求好评或指定评价关键词。

输出：可上线项、待完善项、真实反馈收集表。

待核实：原稿多套评价、价格星级和质量分门槛互不一致，不以其中任一数值作为必须先满足的统一政策。

## M06-02 小范围测试计划

状态：conflicted；原稿：921–961、981–985、2089–2096。

输入：商品价格/贡献空间、广告工具实际选项、可承受损失、目标用户和观测周期。

1. 定义一个测试目标：验证搜索需求、素材吸引力或成交意图，避免一份计划同时承担所有目标。
2. 用用户自定预算上限和停止条件控制试错，先确认归因窗口、数据延迟与费用来源。
3. 记录曝光、点击、加购、成交、实际广告费与退款口径。没有足够样本时不以一天数据定成败。
4. 调整时只改变一个主要因素；扩大预算前检查单笔贡献、库存、履约和现金流，不把花不完预算等同出价过低。

输出：测试假设、设置待确认项、观察表、停止条件。不会自动开启计划或消耗红包。

待核实：工具类型、竞价选项、补贴/赔付范围和条件；原稿固定日预算、核心词数、溢价与周数不直接复制。

## M06-03 用数据决定继续、调整或暂停

状态：reviewed-reference；原稿：950–973、985–986、2098–2102。

输入：同一观察窗口的渠道数据、关键变更记录、商品利润与供货状态。

1. 无曝光先核对是否可售、类目/属性完整、预算和投放状态；有曝光无点击检查匹配与素材。
2. 有点击无成交先检查价格/规格、详情、售后和流量质量，不同时扩大投放并改所有页面内容。
3. 有成交但亏损先区分广告效率、优惠叠加、退货与供货成本；用 M01-03 的一致口径算账。
4. 为继续测试、暂停改进和扩大投入分别写触发条件；活动只在当前官方页面确认资格和成本后列为候选。

输出：本轮结论、证据、下一次只改的一项、复查条件；不承诺若干天内必出单。

待核实：新品标、成长活动、持续投放要求与补贴；原稿时间表只作历史经验，不作当前平台要求。
