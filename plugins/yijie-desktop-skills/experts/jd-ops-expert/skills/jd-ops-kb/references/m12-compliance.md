# M12 商品与经营信息核对

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。本模块用于问题整理，不替代法律意见或平台裁决。

## M12-01 商品信息与资质一致性

状态：reviewed-reference；原稿：1411–1445、1457–1474、1562–1568、1577–1581。

输入：真实商品规格、标签/包装信息、品牌授权与适用证明摘要、拟发布文案。

1. 按材质、用途、尺寸、数量、型号、产地、品牌逐字段对照标题、图文、SKU、后台属性和包装。
2. 对认证、功效、专利、进口来源等主张建立“表述→证据→适用产品→有效范围”表；没有证据就不发布该主张。
3. 区分事实差异、证据缺失和规则未知，不因有外文/外观就推断进口或品牌授权。
4. 提出可核对的文案修改，保留准确事实而非把高风险主张换成同义隐语。

输出：问题、依据、建议修正、待补证明；不承诺“无风险”“必过审”。

待核实：当前类目资质、宣传与标签要求，处罚和赔付需结合适用条款，不能引用原稿金额作为法律结论。

## M12-05 真实经营与证据管理

状态：reviewed-reference；原稿：1475–1487、1502–1512、1549–1561、1582–1586、2225–2228。

输入：用户希望提升的真实经营目标或收到的脱敏通知，不需要真实买家个人信息。

1. 将增长目标转为真实选品、页面、服务、库存和合理投放改进；不设计虚构订单、评价或物流数据。
2. 对通知先记录对象、事项、依据和官方展示的期限；区分 POP、全球购与其他模式，不能继承另一模式的申诉窗口。
3. 将真实采购/销售、履约、服务与活动材料按事件整理，只列必要证据类型，不在对话公开敏感明细。
4. 由用户通过正常入口提交真实说明；未确认事实不要补齐，不以换主体、规避关联或伪造文件处理。

输出：真实经营改进清单或申诉材料组织草稿。它不代表申诉已提交或一定成功。

待核实：通知适用规则、期限与材料要求；72小时/7日冲突保持待核。

## M12-10 内容与售卖范围检查

状态：conflicted；原稿：1539–1548、1569–1589、2243–2252。

输入：直播/视频/商品页面草稿、实际活动事实、类目经营资质与当前规则文本。

1. 将价格、活动期限、库存、功效、服务范围和 AI 使用分别核对真实依据，不能凭原稿一律认定所有限时活动违法。
2. 生成素材要避免歪曲商品，是否需标注、在哪里标注按当前适用规则确认；不将“加标注”当作自动合规。
3. 类目或经营范围变更时先核对官方通知的主体、日期、过渡安排与已有订单处理，不能挂靠其他类目继续承诺。
4. 店铺等级恢复等事项保留实际后台提示和条件，原稿 `>4`/`≥4` 等差异不自行裁定。

输出：可确认事实、待删/待改表述、待核条款和已有订单待办。

待核实：直播/AI、类目准入、店铺考核、生效日期；本包不提供实时法律/平台政策认证。
