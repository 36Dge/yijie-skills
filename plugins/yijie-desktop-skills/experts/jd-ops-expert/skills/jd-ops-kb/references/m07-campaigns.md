# M07 活动准备与复盘

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。

## M07-01 选择适合的活动

状态：reviewed-reference；原稿：990–1004、1022–1041、2101–2114。

输入：当前活动规则、目标商品、库存、毛利空间、店型/类目、商家所处节点。

1. 先写活动目标：新品曝光、库存周转或利润增长；不能只凭活动级别决定参加。
2. 从当前规则整理报名/自动圈选方式、资格、价格、库存、发货、互斥和退出条件；未给条款标待核。
3. 商品按目标分为候选引流款、主销款、利润款，说明选择依据与风险；不伪造店铺等级或销量。
4. 对国家补贴等特殊活动，单列商品资格、真实交易与报备要求，不能依据旧年度简表给确定准入结论。

输出：活动比较表与“不参加/补条件后参加/可由用户继续核实”建议。

待核实：当前日期、活动门槛、补贴范围、申报入口和店型差异，原稿“免报名”和人工报名不能统一套用。

## M07-02 活动前成本与承接准备

状态：reviewed-reference；原稿：1005–1012、1042–1054、2107–2117。

输入：当前优惠叠加规则、库存和补货周期、物流/客服能力、预估销量区间。

1. 按 M05-02 计算正常购物篮的实际收入，不假设活动价不计历史最低价或平台承担全部成本。
2. 用保守销量和较高需求两种用户假设检查库存、发货与售后容量，准备可承接范围和停止条件。
3. 核对活动页、单品页、客服答复中的价格、赠品、起止日期一致；没有真实依据不制造倒计时或稀缺感。
4. 报名后保存产品正常返回的状态与规则版本，未提交/审核中/已通过分开，不能以填写完毕当成功。

输出：成本表、履约/客服准备清单、待确认规则和负责人。

待核实：优惠互斥、活动提交状态和退出规则；等待期按正常流程处理，不提供改图绕过限制的方法。

## M07-03 活动中观察与结束复盘

状态：reviewed-reference；原稿：1042–1061、1277–1281、2115–2120。

输入：活动前基线、活动期流量/成交/退款、花费、库存和异常反馈。

1. 比较同口径的收入、贡献与履约表现；分离平台活动、广告和自然流量，避免重复计算收益。
2. 花费增长但成交不足时先查预算、价格、商品可售与流量来源，不无证据断言同行恶意点击。
3. 检查库存、承诺时效与客服积压，优先解决真实客户问题，必要时由用户按正常后台规则调整。
4. 结束后检查优惠到期与页面还原、未完成订单、退款及库存；留下有效做法、损失原因和下一次修改项。

输出：结果对比、成本与服务影响、可复用经验、待追踪事项。

待核实：活动归因、疲劳期和续报条件，不能用原稿时间推断当前规则。
