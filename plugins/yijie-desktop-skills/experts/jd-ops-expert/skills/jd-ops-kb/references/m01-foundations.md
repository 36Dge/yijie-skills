# M01 核心认知与新店准备

版本：0.1.3；来源：jd-kb-user-provided（指纹见 source-notes.md）；政策核验：NOT RUN。

## M01-01 新店基础设置

状态：reviewed-reference；原稿：11–29、136–143、1762–1763。

输入：店型、实际发/退货地点、可服务地区、客服时段、商品是否已经上架。地址由用户在后台填写，不必把买家信息或详细地址发进对话。

1. 按“店铺信息→配送→退货→客服→商品展示”建立清单，先查空项和互相矛盾项。
2. 在当前京麦的地址管理核对发货与售后退货是否指向实际承接方；代发也须有明确售后接收安排。
3. 比对运费模板、可售地区与实际承运报价，避免页面承诺包邮而履约后另收费。集运是否开放、费用由谁承担单独核实。
4. 核对支付方式、客服可接待时段、短标题和商品素材完整性；开启促销前先做成本核算，不以“设置越多流量越高”作为理由。

输出：设置项、当前值/待填、负责人、完成证据、核实项五列。完成证据是用户确认或脱敏截图，不虚构已操作后台。

待核实：入口名称、运费险/集运条件、费率、促销叠加与实际服务范围；不保证流量提升百分比。

## M01-02 类目与商品是否值得测试

状态：incomplete；原稿：30–41、63–65、1765–1766。

输入：目标商品、采购/履约成本、可承受试错预算、供货稳定性、用户提供的同行与类目数据。

1. 把需求规模、竞争集中度、价格带、售后负担、供应链差异分别列出证据；没有数据的格子保留待查。
2. 比较同一时间范围、同店型和同类目的商品，不能把全站销量与细分类目搜索量直接相除。
3. 检查“买家为什么选该商品”：交付速度、规格差异、可靠凭证、售后承接至少有一个可验证优势。
4. 形成小规模测试假设：目标用户、主卖点、观测指标、预算上限、停止条件。预算由用户确定，专家不自动投放。

输出：可测试/需补数据/暂不建议三种结论之一，并写最关键证据缺口。

待核实：原稿“三个指标”表不完整，不恢复所谓统一机会公式或固定集中度阈值。

## M01-03 经营盈亏与日常判断

状态：reviewed-reference；原稿：58–66、124–132、1798–1802。

输入：售价、采购、物流、包装、平台扣费、优惠承担、退款损失、广告费用，注明含税/未税与订单范围。

1. 先计算用户口径下的单笔贡献：实际收入减去该单可变成本。区分成交额、回款和利润，退款必须用一致分母。
2. 若按“广告归因收入/广告费”定义投产，只能在贡献率与归因收入口径一致、且已考虑退货时，用 `1/贡献率` 作简化保本参考；解释归因与自然成交可能重叠。
3. 日常先看流量、成交、退款和花费变化，再判断是商品、渠道还是成本问题；一次只改变一个主要变量并记日期。

输出：变量表、假设、简化计算与当天优先处理的三个问题。成本缺失时不输出“保证盈利”的预算或 ROI。

待核实：平台实际结算/归因规则；原稿多个保本公式条件不同，不合并为万能公式。
