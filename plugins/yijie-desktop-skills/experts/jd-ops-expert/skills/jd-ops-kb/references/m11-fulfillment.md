# M11 发货与履约

版本：0.1.3；来源：jd-kb-user-provided；政策核验：NOT RUN。

## M11-01 节假日与活动履约准备

状态：reviewed-reference；原稿：1367–1373、2194–2198。

输入：仓库/供应商工作日、真实库存、承运安排、已承诺时效、客服可服务时段。

1. 先按商品和地区确认可发/不可发范围，区分新订单展示承诺与已经接受的订单承诺。
2. 对照当前平台正常设置入口调整未来的售卖、预售或配送时间，核对生效时间，不假设公告能覆盖既有承诺。
3. 页面、店铺公告与自动回复使用同一真实发货安排；无法确定日期时不写确定到货日。
4. 为已接订单建立履约清单与客服联系安排；容量不足时优先限制新增承诺而非隐瞒延迟。

输出：商品/地区、库存、可承诺时间、待确认项、负责人；由用户正常后台设置。

待核实：节假日规则、设置生效延迟、预售资格和活动约束，不照抄历史日期或统一提前天数。

## M11-02 临时延迟与真实物流

状态：reviewed-reference；原稿：1374–1379、1513–1529、2240。

输入：实际无法履约原因、原承诺时间、订单当前状态、正常官方协商功能是否可用。

1. 先核对原承诺和实际库存/揽收状态，记录客观原因与预计恢复范围。
2. 如果平台提供重新约定/报备入口，按当前要求与买家协商；未确认前仍按已有承诺处理，不能假称自动免罚。
3. 只填真实承运方与真实物流状态，不为显示已发货而制造单号或轨迹；不隐藏来自其他渠道的真实履约事实。
4. 保留正常仓库/物流/沟通证据，报告已确认与待确认部分，必要时提出取消/退款等适用方案供用户决定。

输出：事实时间线、可用官方处理路径、材料清单、尚未获得的确认。

待核实：延迟报备条件、发货截止计算和违约处理；原稿多个时刻表达不直接采用。

## M11-04 仓配与托管模式评估

状态：conflicted；原稿：1380–1407、2199–2201。

输入：商品尺寸/重量、销量范围、仓储/发货报价、库存周转、服务模式与合同。

1. 比较自发、代发与平台/第三方仓的完整成本：入库、存储、操作、配送、退货、滞销和补货。
2. 用用户提供的销量范围估算库存与资金占用，不能因预期流量加权就强制入仓。
3. 核对责任交接点：何时算出库/揽收、缺件破损谁处理、客户退货到哪里、怎样正常对账。
4. 托管考核单独读取适用合同；原稿“4–5单延迟2单都超过40%”不严谨，2/5恰为40%，不能代替条款解释。

输出：模式比较、数据缺口、成本敏感项和试用条件，不保证入仓后评分或销量。

待核实：托管考核分档、费率、罚则与适用订单范围。
